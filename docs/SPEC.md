# 弾幕メーカー 仕様書（MVP）

弾幕ステージをユーザーが作って投稿し、世界中で遊び合える iOS ゲーム。イメージはマリオメーカーの「世界のコース」。
試作版（ブラウザ）で確認済みの遊びをそのまま iOS に移植し、投稿・共有・世界対応を足す。

---

## 1. 方針

- 運用費を最小に保つ（ステージは数KBのデータ。動画や画像のユーザーアップロードはしない）
- 投稿は無料・無制限。作り手を減らす課金や制限はかけない
- 最初から日本語＋英語。UI 文字列はすべて String Catalog 経由
- 弾幕の計算は完全に再現可能にする（リプレイ・チート対策の土台）

## 2. 技術構成

| 役割 | 採用 |
|---|---|
| UI | SwiftUI |
| ゲーム画面 | SpriteKit（描画のみ。計算は独立したシミュレーションで行う） |
| バックエンド | Firebase（Firestore / Cloud Functions / Hosting / Storage / Authentication） |
| リージョン | asia-northeast1（東京）1つ |
| 広告 | AdMob（リワード中心） |
| 課金 | RevenueCat（買い切りの広告削除、見た目パック） |
| CI | Xcode Cloud（Xcode 26 / iOS 26 SDK でビルド） |

## 3. ゲーム仕様

### 3.1 クリア条件（作者が作成時に選ぶ）

| モード | 内容 | 時間の選択肢 |
|---|---|---|
| 耐えきる | 指定時間、被弾せずに生き残る | 10 / 20 / 30 / 45 / 60 / 90 / 120 秒 |
| ボスを倒す | 自動ショットでボスの HP を削りきる。制限時間切れは失敗 | 30 / 60 / 90 / 120 / 180 秒 |

ボス戦の設定：
- HP：100〜1000（50刻み）。自機ショットは 0.09 秒ごとに2発、1発1ダメージ
- 動き：動かない / ゆっくり左右 / 速く左右
- HP 残量で第1〜第3段階に切り替わる（2/3、1/3 が境目）。切り替わり時に画面の敵弾を全消去し、1.2 秒「第N段階」を表示して発射を止める

### 3.2 発射台（1ステージ最大8個）

| パターン | 動き | 角度パラメータの意味 |
|---|---|---|
| 放射 | 全方位に等間隔で発射。1回ごとに回転 | 1回あたりの回転角 |
| 渦巻き | 放射と同じ計算で、間隔を短く・弾数を少なくした初期値 | 1回あたりの回転角 |
| 自機狙い | 自機の方向を中心に扇状に発射 | 扇の広がり |
| 雨 | 画面上端のランダムな位置から下向きに落ちる | なし |
| 首ふり扇 | 下向きの扇を左右に振りながら発射 | 振れ幅 |

共通パラメータ：横位置、縦位置、開始秒、終了秒、発射間隔（0.05〜2秒）、弾数（1〜36）、弾の速さ（1〜5、×60px/秒）、色（5色）。
ボス戦では位置と開始・終了は使わず、発射台はボスにくっつき、代わりに「使う段階（全段階 / 第1〜第3段階）」を選ぶ。

### 3.3 プレイ

- 論理画面 360×540。端末サイズに合わせて拡大
- 操作：画面のどこでもドラッグで相対移動（倍率1.2）。指で自機が隠れない
- 当たり判定：自機の判定点と弾の中心の距離が 5.5 未満で被弾
- 開始前 1.2 秒は READY 表示で発射なし
- 発射台の印は撃ち始める 0.6 秒前から点滅表示し、撃ち終わったら消す（後半の発射台を先に見せない）

### 3.4 再現性（最重要）

- 固定タイムステップ 1/120 秒で計算。描画フレームとは切り離す
- 乱数はステージ内容から作ったシードの決定的乱数（mulberry32 相当）のみ使う。`Double.random` や時刻は使わない
- 同じステージ＋同じ入力列なら、必ず同じ結果になること
- リプレイは「各ステップの自機移動量」だけを保存し、圧縮して数KBに収める
- 注意：`sin`/`cos` の結果は OS バージョン間でわずかにずれる可能性がある。サーバー検証を入れる段階で、自前の三角関数テーブルに置き換えるかを判断する

## 4. エディタ

- 上から：クリア条件 → ステージ名・作者名 → 時間（ボス戦なら HP と動きも）→ 発射台カード → テストプレイ / 投稿
- 各発射台カードにループ再生のプレビューを置く。パターン変更やスライダー操作が即座に反映される。自機狙いが分かるように、ダミー自機が左右に動く
- 終了スライダーの最大は「最後まで」。ステージの時間を伸ばしたとき、「最後まで」の発射台は自動で追従する
- 内容を1つでも変えるとクリア確認がリセットされる
- 投稿には、作者本人がテストプレイでクリアすることが必須。クリア時のリプレイを一緒に投稿する

## 5. 世界のステージ（一覧）

- タブ：人気 / 新着 / 高難度（クリア率が低い順、挑戦10回以上） / 急上昇
- ステージ ID 検索（5文字の短縮 ID）
- カード表示：名前、作者、モードのバッジ、挑戦数、クリア数、クリア率、いいね数
- 通報・作者のブロックは各ステージの詳細画面から

## 6. 共有（X など）

### 6.1 共有 URL

- 投稿時にサーバーで短縮 ID（例：`K7X2P`）を発行し、`https://<ドメイン>/s/K7X2P` を共有 URL にする
- Firebase Hosting の `/s/**` を Cloud Functions に向け、OGP 付きの HTML を返す
  - アプリ未インストール：ステージ名・作者・説明を表示し、App Store へ誘導
  - インストール済み：ユニバーサルリンクでアプリが開き、そのステージの詳細画面へ
- `apple-app-site-association` を Hosting で配信

### 6.2 OGP 画像

- 投稿時に Cloud Functions でステージのサムネイル（発射台の位置と、開始数秒後の弾の配置を描いた 1200×630 の画像）を生成し、Storage に保存
- 生成はステージごとに1回だけ。表示のたびには作らない

### 6.3 シェアボタン

- 作者向け（投稿完了画面・自分のステージ）：「『{ステージ名}』の弾幕を作った！クリアできる？ #弾幕メーカー {URL}」
- プレイヤー向け（結果画面）：
  - クリア時：「クリア率{n}%の『{ステージ名}』をクリア！」「{秒}秒でボスを撃破！」
  - 失敗時：「『{ステージ名}』{秒}秒で被弾…誰かクリアして」
- SwiftUI の `ShareLink` を基本にし、X 用に `https://x.com/intent/post?text=` のボタンも置く
- 文言は日本語・英語の両方を用意し、端末の言語で切り替える

## 7. データ構造（Firestore）

```
stages/{shortId}
  authorUid: string
  authorName: string          // 投稿時点の表示名
  name: string                // 最大20文字
  mode: "survive" | "boss"
  durationSec: number
  bossHp: number | null
  bossMove: 0 | 1 | 2 | null
  emitters: [ { t, x, y, s, e, i, c, v, r, k, ph } ]   // 試作のステージ形式と同じ
  formatVersion: 1
  clearReplay: string         // 作者のクリア時の入力（圧縮・Base64）
  ogImagePath: string
  status: "published" | "hidden"
  plays: number
  clears: number
  likes: number
  reports: number
  createdAt: timestamp
  lang: string                // 投稿時の端末言語（表示の参考用）

stages/{shortId}/likes/{uid}
  createdAt: timestamp

users/{uid}
  displayName: string
  createdAt: timestamp
  blockedUids: string[]
  postCount: number

reports/{autoId}
  stageId: string
  reporterUid: string
  reason: "inappropriate_name" | "impossible" | "other"
  createdAt: timestamp
```

### Cloud Functions

| 関数 | 役割 |
|---|---|
| `publishStage`（callable） | 入力の検証（値の範囲・発射台数・NG ワード）、短縮 ID 発行、OGP 画像生成、保存 |
| `submitResults`（callable） | 端末でまとめた挑戦・クリア結果を一括で加算（1プレイごとに書き込まない） |
| `toggleLike`（callable） | いいねの付け外しと件数の更新 |
| `reportStage`（callable） | 通報の保存。一定件数で自動的に `hidden` にし、開発者に通知 |
| `sharePage`（HTTP） | `/s/{id}` の OGP 付きページを返す |

クライアントから `stages` への直接書き込みはセキュリティルールで禁止し、すべて関数経由にする。

## 8. 認証

- 遊ぶだけ：Firebase 匿名認証
- 投稿・いいね・通報：Sign in with Apple（匿名アカウントからリンクして引き継ぐ）

## 9. UGC 審査対応（ガイドライン 1.2）

- 投稿前に利用規約への同意
- ステージ名の NG ワードフィルタ（日本語・英語）
- 通報機能、作者のブロック機能（ブロックした作者のステージは一覧に出さない）
- アプリ内とサポートページに連絡先を掲載
- コメント機能は付けない（評価はいいねのみ）

## 10. 世界対応

- 言語：日本語・英語（String Catalog）。中国語繁体字・韓国語は反応を見て追加
- 配信地域：中国本土のストアは除外（ゲームの配信に政府の許可が必要なため）
- ランキングやイベントの日付の切り替えは UTC
- 利用規約・プライバシーポリシーは日本語と英語の両方を用意

## 11. 収益化

| 種類 | 内容 |
|---|---|
| リワード広告 | 被弾時に「広告を見てその場から復活」（1プレイ1回まで） |
| 買い切り | 広告削除（500〜800円）。購入者は復活が無料・回数無制限 |
| 見た目パック | 自機スキン、弾の形・色、ステージ背景（MVP 後） |

やらないこと：投稿への課金や回数制限、当たり判定などの強化系課金、ステージ開始ごとのインタースティシャル広告。

## 12. MVP の範囲

含める：
- エディタ（プレビュー付き）、両モード、テストプレイ必須の投稿
- 世界のステージ一覧（人気・新着・高難度・急上昇）、ID 検索、いいね
- 共有 URL・ユニバーサルリンク・OGP 画像・シェアボタン（作者・プレイヤー両方）
- 通報・ブロック・NG ワード
- リワード広告での復活、広告削除の買い切り
- 日本語・英語
- 公式サンプルステージ 30〜50 個

MVP 後：
- 職人フォロー
- 週替わりのお題イベント
- 他人のクリアリプレイの視聴
- サーバーでのリプレイ再生によるクリア検証
- プレイ映像の動画シェア
- 見た目パック
