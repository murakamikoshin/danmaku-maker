# 竜王(1.4.0)の組み込み計画

ブランチ `dragon-140`(ranked-match の 1.3.1 から)。元の試射場は worktree `../danmaku-dragon`(ブランチ swipe-mode-spec)の
`art/bosses/patterns/engine.js`(`R.dragon*`)と `art/bosses/dragon/HANDOFF.md`。

## Koshin の決定(2026-11-17)
- 技は **10個全部**、試射場どおりの仕組みで入れる
- 覚醒は **作者が段階ごとに姿を選ぶ**(通常・蒼炎・紫電・白金)
- **ポーズの絵を描き足す**(口を開く・爪を握る・体をひねる)
- 値段 **1,200円 または ボスチケット3枚**。永久買い切りパックには含める(「これから追加される課金も全部」と売っているため)

## 仕組み(ゲーム = DanmakuCore と、サーバー = fullsim.ts で同じ計算)
試射場は 60fps のジェネレーター。ゲームは 120Hz の値型の Simulation(コピーして先読みに使う)なので、
**クロージャを持たない状態機械**で書く。竜王の部分は **偶数ステップ(60Hz)だけ** 進める(試射場のフレーム数をそのまま使える)。

- `DragonState`(Simulation の中、値型)
  - `run`: いま動いている技(種類・姿 lv・プログラムカウンタ pc・待ちフレーム・技ごとの変数)。1つずつ(本体が動くので重ねない)
  - `stage`: 構え 30 → 技 → 硬直 15 → 待機 50(フレーム)。絵の切り替えにも使う
  - `boff`: 本体のずれ(作者の決めた位置・動きに足す)。`pose`: 横向きに飛ぶ姿(-1/0/1)
  - `wind`(px/フレーム)、`pull`(引き寄せ先の種類と強さ)、`bind`(残りフレーム)
  - `zones`: 範囲攻撃(rect / circle / safe / ring / beam)。予告 warn・当たる dur・bind・kill・sweep(尻尾)
  - `eaten`: 星喰いで食べた自機の弾の数
- 竜王の技の発射台は、時間になっても**別の技が動いている間は待つ**(間隔は「最短の間隔」)
- 当たり: 範囲・本体・竜巻・炎の柱は消えない。当たったら 40 フレームは竜王の攻撃が当たらない(ライフ制は従来の2秒の無敵)。
  即死は残りのライフを全部失う。バインドは、その間の入力を無視する
- 風・引き寄せは、入力とは別に自機を動かす(リプレイは入力だけ。サーバーも同じ計算で再現)
- 乱数はシミュレーションの rng(Mulberry32)。引く順番を Swift と TS で同じにする
- 弾: flame / slash / gust / sun / rock / spine / tornado / ember / pshot / body(見えない)。専用の動き(script 30〜)

## 段階ごとの姿
- Stage / Wave に `forms: [Int]?`(段階 1..5 ごとの姿 0..3)。竜王でないボスでは使わない(従来の awaken のまま)
- 技の強さ lv = その段階の姿。絵・弾の色も姿で変わる

## 進め方
1. DanmakuCore: 状態・範囲攻撃・本体・風・引き寄せ・バインド・即死・吸収 + 技10個 + テスト
2. サーバー: fullsim.ts / validate.ts に同じもの + Swift と一致するかのフィクスチャ
3. ポーズの絵(Canva で元絵 → rig → 書き出し)。Koshin の目で確認
4. エディタ: 竜王の技・段階ごとの姿。ゲーム画面: 絵(436コマ)・範囲攻撃の予告・炎(熱の地図)・横向きの姿
5. ショップ・チケット3枚(サーバー claimBossTicket)・ownership(BOSS_BY_LOOK 13)・ASC の商品・文言10言語
6. 敵対的検証 → TestFlight
