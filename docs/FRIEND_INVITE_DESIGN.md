# 友達招待の設計(フェーズ3)

2026-11-09 作成。**コードはまだ入れていません。** 課金・パーツの持ち方・端末の判定に深く関わるので、起きているときに進めます。
ここに、決まっていること、作る順番、あなたにしかできない作業をまとめます。

## 前提の確認

- `appsflyer` ブランチは、`swipe-mode-spec` から見て、SDK(v7)と計測の受け口(`AttributionService.swift`)を足す1コミットだけ(6ファイル、+85行)。合流は簡単。
- 今のパーツの持ち方(`CosmeticsStore.swift`)は、買った商品 ID・広告パターン・無料ボス・チケットの組み合わせ。**招待の報酬は「サーバーが付けて、端末が読む」形を新しく作る必要がある**(称号の `titleState` と同じ作り)。

## 作る順番

1. `appsflyer` ブランチを合流する(ビルド確認)。
2. サーバー: 招待の登録・判定・付与(下の「判定」)と、テスト(エミュレーター)。
3. アプリ: OneLink の受け取り → 登録の呼び出し。ステージ共有のリンクを、招待者 ID 入りの OneLink にする。
4. 報酬の持ち方: `inviteState/{uid}`(本人だけ読める。サーバーだけ書く)に、もらったパーツ・回復ドリンクの記録。`CosmeticsStore` がこれを読んで、`Ownership` に足す。
5. 「初期プレイヤー」パーツ: 招待機能を出す時点のアプリを持っている人全員に配る(**出す版より前にインストールした人だけ**。サーバーで、アカウントの作成日で判定)。
6. 画面: 報酬の一覧、招待の状況(「◯人招待、あと◯人でパーツ」)。

## 判定(サーバー)

- 招待された人が**初めてアプリを開いたとき**、OneLink から招待した人の ID を受け取り、`registerInvite({inviterUid})` を呼ぶ。
  - サーバーで**1回だけ**登録(招待された人の uid をキーにした文書。2回目以降は無視)。
  - **自分で自分を招待**は弾く(`inviterUid == uid`)。
  - 招待した人が実在するか確認する。
- **DeviceCheck**で「この端末は、もう招待された側として使った」を記録する(再インストールでの自作自演の防止)。
  - アプリが `DCDevice.current.generateToken` で作ったトークンを送る → サーバーが Apple の DeviceCheck API の2ビットのうち1ビットを読む・立てる。
  - すでに立っていたら、登録は受け付けるが、**報酬は出さない**。
- 「招待された人が**3回遊んだ**」時点で、サーバーが両方に報酬を付与する。
  - `submitResults` で送られた遊んだ回数を、招待された人ごとに数える(`inviteState` ではなく、招待の文書に `plays` を持つ)。アプリから「報酬ちょうだい」は言わせない。
- 1人の招待者がもらえる**上限**: 10人分まで(10人招待の最上位パーツまでで打ち止め。それ以上は数えるが、報酬は出さない)。

## 報酬(すべて課金で買えない見た目系)

| 条件 | 招待した側 | 招待された側 |
|---|---|---|
| 1人 | おそろいパーツ | おそろいパーツ + 回復ドリンク 2〜3 本 |
| 3人 | 招待者だけのパーツ | |
| 5人 | 招待者だけのパーツ | |
| 10人 | 招待者だけの一番豪華なパーツ | |
| 招待機能を出す時点で持っている人全員 | 「初期プレイヤー」パーツ(あとから来た人は手に入らない) | |

- パーツはエディタでもスワイプ弾幕でも使えるもの(自機スキンを含む)。
- **パーツの中身・見た目は決まっていません**(仮のものでよい、とのことなので、最初は既存のテーマ素材の色違いで作る案)。デザインを決めたら差し替えます。

## あなたにしかできない作業

1. **AppsFlyer**(ダッシュボード): OneLink のテンプレートを作る。招待者 ID は、リンクの `deep_link_sub1` などの引数に入れる。作ったら、テンプレート ID とドメインを教えてください。
2. **Associated Domains**: OneLink のドメイン(`<名前>.onelink.me`)を、アプリの設定(`project.yml` の entitlements)に追加する。Apple Developer の App ID でも Associated Domains を有効にする。
3. **AppsFlyer の開発者キー**(秘密): `Info.plist` の値に設定する(私は中身を見ません。設定の場所と手順だけ書きます)。
4. **DeviceCheck の鍵**(秘密): developer.apple.com の Keys で、DeviceCheck を有効にした鍵(.p8)を作る。鍵 ID とチーム ID(`49Q2CLPBWK`)と一緒に、Firebase の Functions の「シークレット」として登録する。秘密鍵の中身は、私は読みません。
5. 報酬のパーツの**デザインの確認**(仮のものを作ったあと)。

## テスト

- サーバー: 自分で自分を招待・2回目の登録・上限・3回遊んだ時点の付与・DeviceCheck が立っているときの報酬なし、をエミュレーターで。DeviceCheck の呼び出しは、差し替えられる形にして、テストでは偽物を使う。
- アプリ: OneLink の引数の取り出しを、単体テストで。

## 自機を渡す節目(2026-11-10 に変更)

招待した人の自機は、1人ごとに1機ではなく、節目で色ごとにまとめて渡す(サーバーの `SHIP_REWARDS`)。
1人目: オリジナル / 3人目: 鋼の6機種 / 5人目: 雪 / 10人目: 翠 / 20人目: 紅 / 31人目: 影(と、招待限定のボス)。機種は、その色の中から選べる。金の6機は、ランキングなどのごほうび用に取ってある。
