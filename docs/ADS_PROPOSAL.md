# 広告まわりの提案(フェーズ4)

2026-11-09 作成。調べた結果と提案だけで、コードは変えていません。選んでもらえれば実装します。

## 1. 全画面広告の最低間隔: コメントは「2分」、実際の値は 60 秒

- `AdsService.swift` の説明コメント(11 行目)は「前の広告から2分以上」。実際の `minSecondsBetweenAds` は 60 秒。
- 提案: **90 秒**(コメントと値を両方そろえる)。
  - 60 秒だと、「もう一度」を押す短いゲームでは、広告が頻繁に感じられやすい。
  - 120 秒にすると、広告の回数が減り、収益が下がりやすい。
  - 90 秒は、その中間。変えるのは1か所(定数とコメント)。

## 2. 全画面広告が連続しうる問題

全画面広告を出す場所は4つあり、最低間隔を見ているのは1つだけです。

| 場所 | 条件 | 最低間隔 |
|---|---|---|
| 結果画面から次へ(`PlayView` / `showInterstitialIfDue`) | 2回遊ぶごと | 見ている |
| 「もう一度」3回ごと(`PlayView` / `showInterstitialNow`) | 3回ごと | **見ていない** |
| スワイプの「もう一度」2回ごと(`SwipeHomeView`) | 2回ごと | **見ていない** |
| 投稿時の待ち(`PublishFlowView`) | 毎回(広告なしの人は除く) | **見ていない** |
| スワイプの「やめる」・ランキングを閉じる(`showInterstitialIfDue`) | 条件つき | 見ている |

提案(全部に効かせる):
- 全画面広告を出す入口を **1つ**(`AdsService.present(reason:)`)にまとめ、どの場所からでも「前の広告から最低間隔(90 秒)」を必ず見る。
- 例外は、**投稿時の待ち**だけ。もともと待ち時間があるので、間隔が足りなくても出す代わりに、**直後の全画面広告は 90 秒あける**(連続を防ぐ)。
- 「もう一度」の回数カウントは、間隔で見送られたら、**次の回に持ち越す**(カウントを失わない)。

## 3. eCPM が低い原因の確認結果

- **app-ads.txt**: 置かれていて、内容も正しい。
  - 置き場所: `https://danmaku-maker.web.app/app-ads.txt`、`/ja/app-ads.txt`、`/en/app-ads.txt`(3か所とも 200)。
  - 中身: `google.com, pub-3863314847163872, DIRECT, f08c47fec0942fa0`。アプリの本番の広告 ID(`ca-app-pub-3863314847163872/...`)と公開者 ID が一致している。
  - 注意: AdMob の「アプリの確認」は、ASC のマーケティング URL のドメイン(`danmaku-maker.web.app`)の**ルート**の app-ads.txt を見る。反映に最大24時間かかる。
- **ATT の説明画面**: **ない**。`requestTracking()` が、システムの許可ダイアログを、アプリ起動直後にいきなり出している。
  - 許可率が低いと、広告の単価(eCPM)が下がる。一般に、許可の前に「なぜ許可してほしいか」を説明する画面を挟むと、許可率が上がる。
  - 提案: **ATT の前に、説明画面を1枚出す**。
    - 文言(案): 「広告で無料で遊べます。次の画面で『許可』を選ぶと、あなたに合った広告が出ます(許可しなくても遊べます)」。
    - ボタンは「次へ」1つだけ(「許可しない」を目立たせない、など誘導にならないよう、Apple の審査指針を守る)。
    - 出すタイミングは、起動直後ではなく、**最初のステージを1回遊んだあと**。
  - 10 言語の文言が要る。
- **ほかに考えられる原因**:
  - 新しいアプリは、AdMob の審査が済むまで広告がほぼ出ない(単価も低い)。
  - UMP(同意)を外している(`AdsService.swift` 6〜8 行目)。EEA・UK などでは、同意がないと配信が制限される。広告が安定したら戻す案が、コメントに書いてある。

## 4. メディエーション(AppLovin / Unity Ads)の手順

アカウント作成後に実装します。先にあなたがやること:

1. AppLovin(MAX ではなく、AdMob のビディング用)と Unity Ads のアカウントを作り、アプリを登録する。
2. 各社の**アプリ ID・広告ユニット ID**を、AdMob のメディエーション設定に追加する(AdMob コンソール > メディエーション > ビディング)。
3. `app-ads.txt` に、各社の行を追加する(各社のコンソールに「app-ads.txt に追加する行」が出る)。例:
   ```
   applovin.com, <AppLovinのID>, DIRECT, <認証ID>
   unity.com, <UnityのID>, DIRECT, <認証ID>
   ```
   追加は `firebase/hosting/build.mjs` で、デプロイするとき。
4. `Info.plist` の **SKAdNetwork ID** に、各社の ID を追加する(AdMob の公式一覧に、AppLovin・Unity を含む最新が載っている。今は 44 件入っている。足りない分だけ追加)。
5. SDK を入れる(SwiftPM): `GoogleMobileAdsMediationAppLovin` と `GoogleMobileAdsMediationUnity`(AdMob のアダプター)。**Xcode 15.2 で解決できる版**を選ぶ。
6. 初期化の順番: AdMob SDK の `start` のあとは、アダプターが自動で初期化する(追加のコードは基本なし)。
7. 提出前に、ASC の「アプリのプライバシー」に、各社のデータ収集を追記する。

実装の順番(私): 1)最低間隔の入口の一本化、2)ATT の説明画面、3)アダプターの追加(アカウントができたら)。
