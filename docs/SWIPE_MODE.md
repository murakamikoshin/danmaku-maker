# スワイプ弾幕 仕様書（案）

世界のステージから「一番盛り上がる10秒」を切り出し、縦スワイプのフィードで次々に遊ぶモード。
短く・派手に・止まらない。新しい人の入口であり、作り手のステージが遊ばれる場所でもある。

ブラウザの試作：`docs/swipe_prototype.html`（作り物のステージで、遊び心地と演出だけを確かめるもの）

---

## 1. 体験の流れ

1. ホームの「スワイプ」タブを開くと、すぐ1本目が始まる（説明画面なし。初回だけ「ドラッグで動く」を指で示す）
2. 1本 = 10秒。弾幕はすでに飛び交っている途中から始まる
3. 開始 0.5 秒は弾が止まって「GO!」。自機は 1.2 秒間バリアつき（被弾しない）
4. 10秒生き残る → 「CLEAR!」→ 0.9 秒後に自動で次へ
5. 被弾 → スローモーション 0.4 秒 →「あと 3.2 秒」→ 1.2 秒後に自動で次へ
6. どの結果画面でも、上スワイプですぐ次へ、ボタンで「いいね」「フル版で遊ぶ」「作者を見る」「共有」「通報」

1本の最短サイクルは約11秒。待ち時間は合計 1.5 秒以内に収める。

## 2. 操作（ドラッグ移動とスワイプがぶつかる問題）

画面全体のドラッグが自機の移動なので、プレイ中は**スワイプで次に進まない**。

| 場面 | 指の動き | 動作 |
|---|---|---|
| プレイ中 | ドラッグ | 自機の移動（今と同じ。倍率 1.2 の相対移動） |
| プレイ中 | 右上の「スキップ」ボタン | その場で次へ（失敗にも挑戦にも数えない） |
| 結果の表示中 | 上スワイプ／タップ | 次へ |
| 結果の表示中 | 下スワイプ | 同じクリップをもう一度 |

## 3. クリップ（切り出す10秒）

### 3.1 どこを切り出すか
投稿時に Cloud Functions で決め、ステージに保存する。

```
stages/{id}
  clip: { at: number, v: 1 }   // 切り出しの開始秒（ステージ開始からの秒、0.5 秒刻み）。v は選び方の版
```

選び方：
- 自機を初期位置に置いたまま動かさず、無敵でステージを最後まで計算する（`fullsim.simulate` に `observe` を渡す）
- 0.5 秒ごとに「画面内の弾の数」を記録し、10秒の区間ごとの平均が一番大きい区間を選ぶ
- 除外：開始 2 秒以内、ボスを倒した後、連戦の場面転換（intermission）をまたぐ区間
- ステージが 10 秒なら `at = 0`
- 弾が少なすぎる（平均 15 発未満）ステージはクリップを作らず、フィードに出さない

既存のステージは、一度だけ流す関数（`backfillClips`）でまとめて計算する。

### 3.2 途中から始める
端末でも、サーバーと同じ条件（自機は初期位置で止まったまま、無敵）で `clip.at` まで早送り計算する。計算が再現できるので、サーバーが選んだ場面と同じ弾の配置になる。

- `Simulation` に `invincible`（すでにある）を使う。早送りは描画なしで最大 120 秒 × 120 ステップ
- 次の 2 本は裏で先に早送りしておく（スワイプした瞬間に始まるように）
- 早送りが終わった時点で、**自機を一番安全な場所に移す**：画面下半分の 12×8 の候補点のうち、一番近い弾までの距離が最大の点
- 自機を移す操作は `DanmakuCore` に `Simulation.place(at:)` として足す（このモード専用）

### 3.3 勝ち負け
- 全モード共通で「10 秒生き残ればクリア」。ボス戦でもボスを倒す必要はない（倒せたらボーナス点）
- ライフ制・HP 制のステージでも、このモードでは 1 回被弾で終わり

## 4. スコアと連続記録（脳汁の部分）

計算（当たり判定）には関わらない、画面側だけの仕組み。リプレイの検証もしない。

| 要素 | 内容 |
|---|---|
| かすり | 自機の判定点から 18 px 以内を弾が通り抜けたら 1 かすり（1 発につき 1 回だけ） |
| コンボ | かすりが 1.5 秒以内に続くと増える。途切れたら 0 |
| 倍率 | コンボ 10 ごとに ×1 増える（最大 ×8） |
| ボム | かすり 40 回でゲージ満タン → 自動で発動。画面の弾が全部金の得点に変わって自機に吸い込まれる |
| クリア点 | 1000 ×（連続クリア数 + 1）。連続が伸びるほど 1 本の価値が上がる |
| 連続クリア | 被弾で 0 に戻る。自己ベストは端末に保存 |

### 演出（全部入れる）
- かすり：火花、効果音（コンボが増えるほど音程が上がる）、軽い振動（`UIImpactFeedbackGenerator(.light)`）
- コンボ 10 ごと：倍率の数字が画面中央でドンと出る、背景の星が速くなる
- ボム：白フラッシュ、画面の揺れ、金の粒が自機へ飛ぶ音がジャラジャラ鳴る
- クリア：「CLEAR!」が弾けて出る、紙吹雪、点数が数え上がる
- 被弾：スローモーション、赤いフラッシュ、「あと ○.○ 秒」
- 自己ベスト更新：金色の「NEW RECORD」。これだけ特別に長め（1.5 秒）

## 5. フィード（何を流すか）

- 取得元の比率：急上昇 40% / 新着 30% / 人気 20% / 高難度 10%。`clip` があり、`status == "published"` のものだけ
- ブロックした作者、通報済み、自分のステージは除く
- 見たクリップの ID を端末に 500 件まで覚え、同じものを続けて出さない
- 新着を混ぜるのは、投稿したばかりの作り手にも遊ばれる機会を作るため
- オフラインや取得失敗のときは、公式ステージのクリップを流す

## 6. 記録（ステージの数字を荒らさない）

クリップの挑戦は、ステージの `plays` / `clears` / `clearRate` / `hardRate` には**数えない**（10 秒だけの結果でクリア率が変わってしまうため）。

```
stages/{id}
  clipPlays: number
  clipClears: number
  clipLikes は持たない（いいねは通常のいいねと同じ）
```

- `submitResults` の各要素に `kind: "clip"` を足して受ける（なければ今まで通り）
- 急上昇（`trending`）にはクリップのプレイも少しだけ足す（通常の 1/4）
- 「フル版で遊ぶ」が押された回数は Analytics で取る（作り手へ届いた量の目安）

## 7. 広告と課金

- 15 本ごとにインタースティシャル広告（結果画面の後にだけ。プレイの途中には出さない）。広告削除を買った人には出さない
- リワード広告：「連続記録を続ける」。被弾しても連続が切れない。1 回の連続につき 1 回まで（広告削除を持っている人は無料で 1 回）
- 有料のガチャや、お金で連続記録を買う仕組みは入れない

## 8. 実装の分担

| 場所 | やること |
|---|---|
| `DanmakuCore` | `Clip.swift`：区間の選び方、早送り、安全な位置。`Simulation.place(at:)`。テストは「サーバーの選び方と同じ秒になる」「早送り後の弾の数がサーバーと一致する」 |
| `firebase/functions` | `publishStage` でクリップを計算して保存。`backfillClips`。`submitResults` の `kind: "clip"` |
| `DanmakuApp` | `SwipeFeedView`（フィードと結果のボタン）、`SwipeScene`（SpriteKit。かすり・ボム・演出）、先読み、タブの追加 |

## 9. まだ決めていないこと

- スコアのランキングを作るか（作るなら、かすりも `DanmakuCore` で計算してリプレイで検証する必要がある）
- 1 本の長さを 10 秒に固定するか、7 / 10 / 15 秒をステージごとに変えるか
- 作者に「あなたのステージがスワイプで ○ 回遊ばれました」と通知するか
