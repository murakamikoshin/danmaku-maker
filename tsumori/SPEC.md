# ガマンの塔（仮称） 仕様書（MVP）

買うのをガマンした分だけ自機が強くなり、「誘惑の塔」を上っていく iOS ゲーム。
つもり貯金（使ったつもりで使わなかったお金）を記録すると、その額に応じてレベルが上がる。
試作版（ブラウザ）は `tsumori/prototype.html`。

---

## 1. 方針

- **ゲームの進み具合は、ガマンした額でしか決まらない。** 腕前は「推奨より少し低いレベルでも勝てる」程度に効くが、塔を上る速さは貯金のペースで決まる
- **記録は1タップ。** 開いて、ガマンした物を押して、閉じる。これが5秒で終わることを最優先にする
- **嘘をつく理由を減らす。** 一度に大金を入れても、すぐには強くならない（1日の反映上限）。続けた日数のほうが効く要素（ボム・残機）を用意する
- **お金を使わせない。** ガチャ、スタミナ、強化アイテムの課金はしない。「お金を使わないほど強い」と矛盾するため
- **合計額は本当の金額で見せる。** 強さとは別に、いくら貯まったかを常に円で表示する
- サーバーは使わない。記録は端末の中だけ（iCloud バックアップは MVP 後）

## 2. 用語

| 用語 | 意味 |
|---|---|
| ガマン | 買うのをやめた物の記録。品名と金額を持つ |
| 累計 | 取り消していないガマンの合計額。画面に円で出す |
| 反映済み | 累計のうち、レベルに反映された額 |
| 繰り越し | 累計のうち、まだレベルに反映されていない額（＝累計 − 反映済み） |
| 1日 | 午前4時で区切る（深夜0時〜4時の記録は前の日に入る） |
| 連続日数 | ガマンを1件以上記録した日が何日続いているか |
| おやすみ券 | 記録しなかった日に自動で使われ、連続日数を守る券 |

## 3. ガマンの記録

### 3.1 プリセット（初期値）

| 品名 | 金額 |
|---|---|
| コンビニコーヒー | ¥150 |
| ペットボトル飲料 | ¥160 |
| コンビニおやつ | ¥200 |
| カフェのドリンク | ¥550 |
| ランチの外食 | ¥1,000 |
| タクシー | ¥1,500 |
| 飲み会の2次会 | ¥3,000 |
| トレカ 1パック | ¥180 |
| トレカ 1BOX | ¥5,500 |
| ネットのついで買い | ¥2,000 |

- プリセットはユーザーが追加・編集・削除・並べ替えできる。最大24個
- プリセット以外に「金額を入力して記録」（品名は任意、空なら「その他」）
- 金額は1件 ¥10〜¥100,000、1円単位。1日に記録できるのは30件まで

### 3.2 取り消し（やっぱり買った）

- 履歴の各行に「やっぱり買った」ボタン。2回押しで確定する（誤タップ防止）
- 取り消したガマンは、記録した日から無かったものとして計算し直す（4.1 の計算は全履歴から毎回出し直す純粋な計算なので、それで整合が取れる）
- その結果レベルが下がることがある。下がったときはそのまま表示し、責める演出はしない
- 取り消しの取り消しは無し（もう一度記録してもらう）

## 4. 強さの計算

すべて記録の一覧と「今日の日付」だけから決まる純粋な計算にする（`TsumoriCore` に置き、単体テストで固定する）。

### 4.1 反映（1日 ¥3,000 まで）

最初の記録日から今日まで、1日ずつ次を繰り返す。

```
使える額 = 前日までの繰り越し + その日の記録額
その日の反映 = min(3,000, 使える額)
反映済み += その日の反映
繰り越し = 使える額 − その日の反映
```

- 今日の分もすぐ反映する（記録した瞬間に強くなる）
- 例：BOX 1つ ¥5,500 をガマン → 今日 ¥3,000、明日 ¥2,500 が反映される
- ホームに「今日の反映 ¥x / ¥3,000」と「繰り越し ¥y（明日以降に反映）」を出す

### 4.2 レベル

レベル L に必要な反映済み額：

```
必要額(L) = 30 × L² + 70 × L     （上限 Lv99 = ¥300,960）
```

Lv0→1 は ¥100、そこから1レベルごとに必要額が ¥60 ずつ増える（Lv L→L+1 は ¥(100 + 60L)）。

| Lv | 必要額（累計） | 次のLvまで |
|---|---|---|
| 1 | ¥100 | ¥160 |
| 5 | ¥1,100 | ¥400 |
| 10 | ¥3,700 | ¥700 |
| 20 | ¥13,400 | ¥1,300 |
| 30 | ¥29,100 | ¥1,900 |
| 50 | ¥78,500 | ¥3,100 |
| 70 | ¥151,900 | ¥4,300 |
| 99 | ¥300,960 | — |

前回案の `10 × log10(累計÷100)` は後半の伸びが遅すぎた（¥10万から次のレベルまで ¥500/日 ペースで52日）ため、この2次式に変えた。後半でも1レベルが ¥500/日 で約9日。

### 4.3 レベルで決まるもの（攻撃）

| 項目 | 式 |
|---|---|
| 火力（毎秒のダメージ） | 10 × 1.04^L（1レベルで4%、10レベルで約1.5倍。Lv99 で 486） |
| 弾の列数 | 1列。Lv10・25・45・70 で1列ずつ増え、最大5列 |
| 連射間隔 | 0.10 − 0.04 × L ÷ 99 秒（Lv99 で 0.06 秒） |
| 1発の威力 | 火力 × 連射間隔 ÷ 列数（火力から逆算する） |

| Lv | 列数 | 火力 |
|---|---|---|
| 0 | 1 | 10 |
| 10 | 2 | 15 |
| 25 | 3 | 27 |
| 50 | 4 | 71 |
| 70 | 5 | 156 |
| 99 | 5 | 486 |

- 火力は指数で伸ばす。威力を「1 + L÷20」のような足し算にすると、後半は10レベル差でも1割しか違わなくなり、ガマンしなくても腕前だけで塔を上れてしまうため
- 列が増えても火力は増えない。列は弾が広がって当てやすくなる効果（動くボスに当てやすい・見た目が派手になる）。列が増えるレベルは「◯列ショット解放」と大きく演出する
- 当たり判定の大きさ・自機の速さはレベルで変えない（腕前の要素を残す）

### 4.4 連続日数で決まるもの（守り）

| 項目 | 式 |
|---|---|
| ボム | 1 + floor(連続日数 ÷ 3)、最大4個 |
| 残機（被弾しても続けられる回数） | 連続7日以上で1、30日以上で2 |

- 「今日」まだ記録していなくても、連続日数は昨日までの値で表示する（今日の終わりまでは途切れない）

### 4.5 おやすみ券

- 毎週月曜（4時区切り）に1枚もらえる。持てるのは2枚まで。最初に記録した週にも1枚もらえる
- 記録しなかった日が過ぎたとき、連続日数が1以上で券があれば自動で1枚使い、連続日数を守る（その日は日数に数えない）
- 券がなければ連続日数は0に戻る

### 4.6 レベル1年分の目安

| 毎日のガマン | 1週間 | 1か月 | 3か月 | 半年 | 1年 |
|---|---|---|---|---|---|
| ¥300 | Lv7 | Lv16 | Lv28 | Lv41 | Lv59 |
| ¥500 | Lv9 | Lv21 | Lv37 | Lv53 | Lv76 |
| ¥1,000 | Lv14 | Lv30 | Lv53 | Lv76 | Lv99 |

## 5. ゲーム：誘惑の塔

### 5.1 構成

- 全100階。1階ごとにボス1体（弾幕のボス戦。弾幕メーカーの「ボスを倒す」モードと同じ遊び）
- 挑戦は無料・回数無制限。クリアすると次の階が開く。クリア済みの階はいつでも遊び直せる
- **推奨レベル = 階 − 1**（1階は Lv0、100階は Lv99）
- 階の一覧には推奨レベルと、自分のレベルとの差を色で出す（余裕：自分が推奨以上 / 適正：推奨−5まで / きつい：それ未満）

### 5.2 ボスの名前（10階ごとに誘惑の種類が変わる）

| 階 | ボス |
|---|---|
| 1〜10 | コンビニの誘惑 |
| 11〜20 | 自販機の誘惑 |
| 21〜30 | カフェの誘惑 |
| 31〜40 | サブスクの誘惑 |
| 41〜50 | タイムセールの誘惑 |
| 51〜60 | 送料無料まであと少しの誘惑 |
| 61〜70 | 限定品の誘惑 |
| 71〜80 | 新作パックの誘惑 |
| 81〜90 | 推しグッズの誘惑 |
| 91〜100 | 衝動買いの化身 |

表示は「コンビニの誘惑 3」のように番号をつける（100階だけ「衝動買いの化身・真」）。

### 5.3 ボスの強さ

- HP = 20 × 推奨レベルでの火力 = 200 × 1.04^(階−1)（四捨五入）。推奨レベルの自機が全弾当てると20秒、避けながらだとおよそ25秒で倒せる
  - 例：1階 200、11階 296、26階 533、51階 1,421、100階 9,712
- 制限時間 60 秒。時間切れは失敗
- HP 残量 2/3・1/3 で第2・第3段階。切り替わり時に敵弾を全消去し、1.0 秒発射を止める
- 倒すまでの目安（命中8割として）：推奨ぴったり 25秒、5レベル低い 30秒、10レベル低い 37秒、20レベル低い 55秒、25レベル低いと 67秒で間に合わない。どの階でも同じ比率になる

### 5.4 ボスの弾幕（階から自動生成）

- 階番号から作った乱数シード（mulberry32）で決まる。同じ階はいつも同じ弾幕
- 使うパターンは弾幕メーカーの5種（放射・渦巻き・自機狙い・雨・首ふり扇）
- 発射台の数：第1段階は1個。第2段階は30階以上で2個。第3段階は15階以上で2個、60階以上で3個
- 難しさ t = (階 − 1) ÷ 99 として、発射間隔・弾数・弾の速さを t に合わせて線形に強くする（速さは 95→175 px/秒）。具体的な値は試作で決め、確定値を `TsumoriCore` の生成関数に固定する
- 公式ステージと同じく StageBot（弱いボット）で全100階を回し、「推奨レベルの弱いボットで3割以上クリア」を満たすか確認する

### 5.5 操作と判定

- 弾幕メーカーと同じ：論理画面 360×540、どこでもドラッグで相対移動（倍率1.2）、当たり判定は距離 5.5 未満、開始前 1.2 秒は READY
- ショットは自動。列は 1.5° ずつ広がる（5列でもボスの近くではほぼ全弾当たる幅）
- ボム：画面のボタンで使う。敵弾を全消去し、1.5 秒無敵
- 被弾：残機があれば1減らして敵弾を全消去し、1.5 秒無敵。残機0で被弾すると失敗

### 5.6 結果画面

- クリア：「◯階 クリア！」→「次の階へ」
- 失敗：ボスの残りHP（％）を出す。自分のレベルが推奨より低いときは
  **「推奨 Lv◯ まで、あと ¥◯ のガマン（最短◯日）」** を出す。最短日数は 1日 ¥3,000 の上限と繰り越しから計算する
  - ここがゲームと貯金をつなぐ一番大事な画面。「ガマンを記録」ボタンを並べて置く
- 広告で復活はしない（強さはガマンで買うもの、という筋を通す）

## 6. 本当の貯金（MVP 後半に入れる）

- 毎週日曜の夜に「今週のつもり貯金 ¥◯ を本当の貯金に移した？」と聞く（通知＋ホームのカード）
- 「移した」を押した額を「確定額」として別に数える。確定額で自機の見た目（スキン）が手に入る（¥1万・¥3万・¥5万・¥10万・¥30万）
- 確定額は強さには影響しない。強さはあくまで記録で決まり、確定は「現実の貯金」を後押しするご褒美

## 7. 通知

- 1日1回まで。時刻はユーザーが選ぶ（初期値 21:00）
- その日まだ記録していなければ「今日ガマンしたもの、ありますか？」
- 連続3日以上で、券がなく、まだ記録していない日は「連続◯日が今夜で途切れます」に変える
- 記録済みの日は送らない
- 初回起動ではなく、最初のガマンを記録した直後に通知の許可を求める（許可される率が高い）

## 8. 画面

| 画面 | 内容 |
|---|---|
| ホーム | 累計（円）、Lv と次のLvまでの残り額、今日の反映 / 繰り越し、連続日数・券、火力・列数・ボム・残機、**プリセットのボタン群（ここで1タップ記録）**、金額入力、今日の記録 |
| 履歴 | 日ごとの一覧、取り消し |
| 誘惑の塔 | 階の一覧（推奨Lv・差の色・クリア済み） |
| プレイ | ボス戦。HPバー、残り時間、残機、ボム |
| 結果 | 5.6 の内容 |
| 設定 | 通知時刻、プリセット編集、データの書き出し（CSV） |

記録したときは、レベルが上がれば「Lv12 → 13」と火力の増え方をトーストで出す。上がらなければ「次のLvまで あと¥◯」を出す。

## 9. データ（端末内、SwiftData）

```
Entry
  id: UUID
  createdAt: Date
  day: Int                 // 4時区切りのローカル日付を通し番号にしたもの
  presetId: UUID?
  name: String             // 最大20文字
  amount: Int              // 10〜100,000
  canceledAt: Date?

Preset
  id: UUID
  name: String
  amount: Int
  order: Int

Progress
  highestCleared: Int      // 0〜100
  bestTimes: [Int: Double] // 階ごとの最速クリア秒

Settings
  notifyHour: Int, notifyMinute: Int
```

- 反映済み・繰り越し・レベル・連続日数・券は保存しない。毎回 Entry から計算する（4章）
- 時計を戻すズルは対策しない（一人用なので損するのは本人だけ）。ただし未来の日付の記録は作れないようにする

## 10. 収益化

| 種類 | 内容 |
|---|---|
| バナー広告 | ホーム下部のみ。プレイ中と記録の瞬間には出さない |
| 買い切り | 広告削除 ¥300 |

やらないこと：ガチャ、スタミナ、強化アイテム、広告での復活、インタースティシャル広告。

## 11. 技術構成

| 役割 | 採用 |
|---|---|
| 置き場所 | このリポジトリに別アプリのターゲット `TsumoriApp` として追加（`project.yml`） |
| 計算 | 新しい Swift Package `TsumoriCore`（反映・レベル・連続日数・券・ボス生成。UIKit 非依存） |
| 弾幕 | `DanmakuCore` の Simulation をそのまま使う。塔の各階を `Stage` データとして生成して渡す |
| UI | SwiftUI、プレイ画面は SpriteKit（弾幕メーカーと同じ） |
| 保存 | SwiftData（端末内のみ） |
| 通知 | UserNotifications（ローカル通知） |
| 広告・課金 | AdMob、StoreKit 2（弾幕メーカーと同じ作り） |

`DanmakuCore` に足す必要があるもの：自機ショットの列数・威力・連射間隔を外から渡せるようにする、残機とボムの仕組み。

## 12. MVP の範囲

含める：
- 記録（プリセット・金額入力・取り消し）、反映・レベル・連続日数・おやすみ券
- 誘惑の塔 100 階、結果画面の「あと¥◯」
- 毎日の通知
- バナー広告、広告削除
- 日本語のみ（英語は MVP 後）

MVP 後：
- 本当の貯金（6章）とスキン
- ホーム画面ウィジェット（累計と Lv）
- iCloud バックアップ
- CardAlertHub 連携：値下がり通知を見送ったときに「このカードをガマン」を1タップで記録
- 英語対応（通貨はその国のものにし、上限やレベル式は通貨ごとに係数を持つ）

## 13. 試作で確かめること

- 最初の3日で「強くなった」と感じるか（¥500/日 で 3日目に Lv6）
- 列が増えるレベル（10・25）の手応え
- 推奨レベルぴったりで、ボスを25秒前後で倒せるか。弾幕が強すぎ・弱すぎにならないか（5.4 の数値を決める）
- 1日 ¥3,000 の上限が、高額のガマンをした人に不満を与えないか

試作には「次の日へ」「7日進める」などの日付を進めるボタンがある（本番には入れない）。
